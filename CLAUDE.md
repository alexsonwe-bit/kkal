# «Калории» — дневник питания

Русскоязычный дневник калорий и БЖУ. PWA для iPhone: ставится через Safari → «На экран Домой», после загрузки работает офлайн. Приложением пользуется конкретный человек каждый день — его данные важнее новых функций.

- Приложение: https://alexsonwe-bit.github.io/kkal/
- Отдельная инструкция: https://alexsonwe-bit.github.io/kkal/guide.html

Последнее подтверждённое состояние (ноябрь 2026): кэш `kkal-v7`, приложение работает, ошибка с исторической нормой исправлена. После этого новые функции не внедрялись.

## Как работать с владельцем

- Общаться по-русски.
- Не начинать новые функции без выбора владельца (см. «Идеи»).
- Перед обновлением напомнить сделать экспорт JSON (резервную копию).
- Не просить пароли, ключи и другие секреты в переписке.
- Не утверждать непроверенное: что JSON содержит фото, что iPhone обновится с одного перезапуска, что сайт открывается из России без VPN.

## Репозиторий публичный

Не коммитить сюда личные данные, экспорты дневника, API-ключи, адреса серверов.

## Файлы

Сборки и сервера нет.

- `index.html` — весь интерфейс, стили, логика, база продуктов и встроенный гайд.
- `guide.html` — отдельная инструкция, чтобы отправить до установки.
- `sw.js` — офлайн-кэш, network-first.
- `manifest.webmanifest`, `icon-180.png`, `icon-192.png`, `icon-512.png`. Иконку домашнего экрана не менять.
- `README.md`.

Текст гайда продублирован в `index.html` и `guide.html` — правки вносить в обе копии.

## Деплой

GitHub Pages: Settings → Pages → Deploy from a branch → `main` → `/ (root)`. Владелец обычно загружает файлы сам: Add file → Upload files → Commit changes.

1. При изменении `index.html` или `guide.html` самому повысить `CACHE` в `sw.js` (`kkal-v7` → `kkal-v8`) и включить `sw.js` в список изменённых файлов. Прямо сказать владельцу: «версию уже поднял, руками менять не нужно».
2. Передавать только изменившиеся файлы — сравнить с опубликованными.
3. После загрузки проверить отдельно репозиторий (raw.githubusercontent.com) и сайт (Pages). Сравнивать по хешам/побайтово: одинаковый размер `sw.js` не доказывает одинаковую версию. Pages отдаёт `Cache-Control: max-age=600` — изменения приходят с задержкой.
4. Сообщать о готовности только когда все файлы совпали.
5. Не предлагать переустанавливать приложение или чистить Safari без необходимости — это может стереть дневник.

## Хранение данных

- Дневник, профиль, свои продукты, настройки — `localStorage`, ключ `kkal.v1`.
- Фото — IndexedDB `kkal`, хранилище `photos`. Хранятся отдельно от JSON-экспорта.
- SW-кэш файлов отделён от пользовательских данных.
- **Не менять ключи и структуру хранения без совместимой миграции.**
- Очистка данных браузера может удалить дневник — поэтому экспорт.

## Возможности

Пять вкладок: Дневник, Добавить, Прогресс, Профиль, Гайд.

- Поиск продуктов, вес, расчёт калорий и БЖУ; завтрак, обед, ужин, перекус.
- Нажатие на строку в Дневнике — правка веса или удаление.
- Свои продукты: создание, изменение названия/КБЖУ/меры, удаление; штучные меры («1 пачка · 200 г»).
- Вода, взвешивания, графики калорий и веса, средние.
- Автоматическая или ручная дневная норма. Экспорт/импорт JSON. Фото к записи.

## База продуктов

282 продукта в `index.html`, блок `FOOD_RAW`, формат `Название|ккал|белки|жиры|углеводы|категория|мера`. Это справочные значения без подтверждённого источника — не называть её проверенной официальной базой. Свои продукты вводятся с упаковок или по рецептам.

## Норма

- Миффлин — Сан-Жеор, поправки на активность и цель. Белок 1,6–1,9 г/кг, жиры изначально 0,9 г/кг, углеводы — остаток (в коде есть доп. ограничения). Цели можно задать вручную. Это расчётный ориентир, не медицинское назначение.
- **Историческая норма:** у каждого дня хранится снимок `day.norm`. Норму дня читать через `dayTargets(k)`, текущую — через `targets()`. Изменения Профиля применяются с сегодняшнего дня (`refreezeFromToday()`). На графике норма — ступенчатая линия. Записи без снимков обрабатывает `backfillNorms()` при загрузке/импорте (приблизительно, если прежние вес и настройки не сохранились).
- Раньше смена веса пересчитывала прошлые дни задним числом — не допускать регресса.
- Историческое взвешивание (день в Дневнике → Прогресс → вес) задаёт норму с этого дня до следующего взвешивания. Текущий вес в Профиле меняет только сегодняшнее взвешивание. Для новых взвешиваний рекомендовать Прогресс.

## Поиск

- `stem()`, словарь `SYNONYMS`, обороты `PHRASES`, запасной поиск по любому слову; свои продукты в приоритете.
- Раньше «яйца», «картошка», «греча», «сосиска» ничего не находили — при расширении базы проверять единственное/множественное число и разговорные названия.
- Известные огрехи ранжирования: «картошка» первой даёт фри, «овсянка» — овсяноблин; «кофе с молоком» → латте (приближение).

## Свои продукты и записи

- Запись дневника хранит снимок КБЖУ, а не живую ссылку. Связь — поле `src`, поиск связанных записей — `usesOfProduct(id)`.
- При изменении продукта — галочка «Пересчитать N записей» (необязательно). Удаление продукта не удаляет записи.
- Карандаш только у своих продуктов (поиск, Недавние, Мои продукты). Встроенные не редактируются.
- Результат поиска — контейнер `.resrow` с двумя отдельными кнопками. Не вкладывать кнопку в кнопку.

## AI-распознавание фото

Выключено и фактически не используется (нет способа оплатить API). Реализация: прямой запрос из браузера к Anthropic Messages API, ключ вводится в Профиле и хранится на устройстве, заголовок `anthropic-dangerous-direct-browser-access: true`, ответ по JSON Schema через `output_config.format` (объект с массивом `dishes`), `max_tokens: 4096`, `effort: "low"`, обработка отказа модели; assistant-prefill удалён (давал 400). В коде модели `claude-opus-5` / `claude-sonnet-5` — перед включением сверить актуальные идентификаторы и API с документацией. Успешного запроса с реальным ключом не было, только моки. Посредник за рубли и GigaChat обсуждались, не подключены.

## Дизайн

- Спокойный читаемый интерфейс, мягкая зелёная палитра, светлая и тёмная темы. Главное — кольцо калорий, БЖУ и цифры.
- Кот: максимум один на экран, только в пустых состояниях; исчезает при появлении записей; прошлый пустой день — спящий кот. Полная кошачья тема отвергнута.
- Иконки приёмов: рассвет, миска, месяц, кошачья лапка. Стрелка › у записи — подсказка, что её можно править.
- Встроенный гайд — на стилях приложения; `guide.html` — Literata / Golos Text.
- Не использовать Grid для `<li>` со смешанными `<b>` и текстом — маркер позиционируется отдельно.
- Проверять ширину 375 px и обе темы.
- Никаких серий, наказаний за пропуски и навязчивых уведомлений.

## Проверить следующему разработчику

- Не перезаписывает ли историческое взвешивание намеренно заданные нормы внутри интервала.
- Переключение автоматических целей на ручные: в прежнем коде auto выключался до считывания вычисленных значений.
- Экспорт фото и восстановление из JSON.
- `sw.js`: перед `cache.put` проверять `response.ok`, чтобы не кэшировать неуспешные ответы.
- Старые тесты не считать полной проверкой текущего Safari/iOS.

## Идеи (обсуждены, не реализованы — только по выбору владельца)

Повтор вчерашнего/выбранного приёма с весами; запоминание последнего веса порции; свой продукт на основе встроенного; конструктор рецептов (ингредиенты + вес готового блюда → КБЖУ на 100 г); быстрый ввод только калорий; ненавязчивое напоминание об экспорте; раздел «Часто ем»; лучшее ранжирование поиска.
